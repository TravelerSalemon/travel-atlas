# 个人旅行图鉴网站

一个无需数据库、无需构建工具的静态个人旅行网站。旅行数据来自你的现有旅行日志；地图、统计、城市卡片和景点列表全部由数据自动生成。

## 1. 工程结构

```text
travel_website/
├─ index.html                   # 页面结构
├─ css/
│  └─ styles.css                # 全站样式
├─ js/
│  └─ app.js                    # 自动统计、地图下钻、筛选、详情抽屉
├─ data/
│  └─ travel-data.js            # ★ 日常维护主要只改这个文件
├─ assets/
│  ├─ favicon.svg
│  └─ photos/
│     ├─ provinces/             # 省级封面图
│     ├─ cities/                # 城市封面图
│     └─ spots/                 # 景点照片
├─ .github/workflows/pages.yml  # GitHub Pages 自动公开部署
├─ .nojekyll
└─ THIRD_PARTY.md
```

## 2. 本地预览

不要直接双击 `index.html` 作为最终测试，因为浏览器对 `file://` 下的网络请求可能有限制。进入工程目录后启动一个静态服务器：

```bash
python -m http.server 8000
```

然后访问：

```text
http://localhost:8000
```

地图边界需要联网加载，其他旅行内容不依赖地图接口。

## 3. 最常见的修改

### 3.1 新增景点

打开 `data/travel-data.js`，找到对应城市：

```js
nature: [
  '西湖',
  '太子湾公园',
  '新增的自然景点'
],
culture: [
  '雷峰塔',
  '浙江大学'
]
```

保存即可。全站景点总数、城市景点数、省级合计等会自动更新。

### 3.2 给景点增加照片

普通景点可以写成字符串；需要照片时改成对象：

```js
{
  name: '故宫博物院',
  photos: [
    'assets/photos/spots/beijing-gugong-01.jpg',
    'assets/photos/spots/beijing-gugong-02.jpg'
  ],
  district: '东城区'
}
```

`district` 是可选字段。对北京、上海等直辖市，填写区名后，区级地图会自动高亮对应行政区。若一个地理对象跨越多个区，可改用 `districts` 数组，例如：

```js
{
  name: '黄浦江',
  districts: ['黄浦区', '浦东新区']
}
```

区级统计、地图高亮和详情筛选都会自动识别这些字段。

### 3.3 新增城市

在所属省份的 `cities` 数组中增加：

```js
{
  name: '黄骅',                 // 网站显示名称
  mapName: '沧州市',           // 地图上对应的地级行政区名称
  adcode: '130900',            // 对应行政区划代码
  date: '2026.09.25',
  cover: 'assets/photos/cities/黄骅.jpg',
  note: '如果旅行记录是县级市，可说明其地图归属。',
  nature: ['渤海'],
  culture: []
}
```

注意：当前地图按“省 → 地级行政区”下钻。如果你记录的是县级市/景区，可以像“长白山”一样，把 `mapName` / `adcode` 指向其所属地级行政区，同时保留自己希望显示的 `name`。

### 3.4 新增省级行政区

在 `provinces` 数组中新增：

```js
{
  name: '天津市',
  adcode: '120000',
  cover: 'assets/photos/provinces/天津.jpg',
  cities: [ /* 城市记录 */ ]
}
```

不需要修改首页统计，也不需要另外维护“已去过省份数量”。

## 4. 图片规则

- 省级图片：`assets/photos/provinces/`，推荐横向 4:3 或 3:2。
- 城市图片：`assets/photos/cities/`，推荐横向 4:3 或 3:2。
- 景点照片：`assets/photos/spots/`，数量不限。
- 图片不存在时会显示设计好的渐变占位背景，因此可以先维护旅行数据，再慢慢补照片。

## 5. 地图逻辑

网站使用 ECharts 渲染行政区地图：

1. 全国地图：根据 `province.adcode` 自动识别已到访省份并高亮。
2. 点击省份：加载该省的市级 GeoJSON。
3. 省内地图：根据 `city.adcode` 自动高亮已记录城市。
4. 点击已记录城市：打开日期、自然/人文景点与照片详情。
5. 北京、上海等直辖市：省级下钻后显示区级边界。当前北京、上海景点已经补充 `district` / `districts` 信息；地图会按区高亮，右侧统计显示“已到访区”，点击区名可只查看该区景点。

地图有两个边界数据源，主源失败时自动尝试备用源。旅行数据本身始终保存在你的工程里。

## 6. 公开部署（GitHub Pages）

本工程已经包含 `.github/workflows/pages.yml`。

1. 在 GitHub 新建一个 **Public（公开）** 仓库，例如 `travel-atlas`。
2. 把本工程目录中的全部文件上传/推送到仓库 `main` 分支。
3. 打开仓库 **Settings → Pages**。
4. `Build and deployment` 的 Source 选择 **GitHub Actions**。
5. 推送后工作流会自动发布；生成的网址通常形如：
   `https://你的用户名.github.io/travel-atlas/`

只要仓库与 Pages 站点保持公开，网站就是任何人都可以访问的，而不是“仅自己可见”。

也可以把同一文件夹直接部署到 Cloudflare Pages / Netlify，它们同样不需要额外构建命令。

## 7. 修改后快速校验

工程内置了一个无需安装依赖的数据检查脚本：

```bash
node scripts/validate-data.js
```

它会检查省份/城市 `adcode`、空景点名称和重复记录，并打印当前自动统计结果。

## 8. 重要维护原则

- **不要手写统计数字。** 所有数字由 `app.js` 从数据数组计算。
- **旅行数据只维护一份。** 优先只改 `data/travel-data.js`。
- `adcode` 决定地图高亮位置；显示名称和地图行政区名称可以不同。
- 旅行数据与地图边界分离，因此以后地图源更新，不会影响你的旅行记录。

## 地图匹配机制（2026-09-29 修复）

全国和省级地图现在采用“双重匹配”：

1. 优先使用 GeoJSON 中的 `adcode` 与 `travel-data.js` 匹配；
2. 如果地图源没有提供可用的 `adcode`，则自动规范化行政区名称后匹配，例如 `安徽` / `安徽省`、`北京` / `北京市`、`新疆` / `新疆维吾尔自治区` 会被视为同一行政区；
3. 全国层面还内置省级行政区标准 `adcode` 作为未到访省份下钻时的兜底，因此即使主 GeoJSON 只提供名称，也可以继续进入省级地图；
4. 已到访省份或城市会以重点色显示，并在地图标签下显示“已到访”。

如果更新代码后浏览器仍显示旧效果，请先强制刷新：Windows 浏览器使用 `Ctrl + F5`。`index.html` 已为数据脚本和地图脚本加入版本参数，以减少浏览器缓存旧 JavaScript 的情况。


## 全国地图层级说明与故障排查

全国视图必须直接加载包含省级行政区边界的 `100000_full.json`。当前版本会自动检查 GeoJSON 层级：如果某个地图源只返回“中华人民共和国”单个整体轮廓，会自动跳过，不会再把 `100000` 误当成省份。

正常情况下，全国地图的侧栏标题应为“中国 · CHINA”，地图上已到访省份会高亮并显示“已到访”。点击省份后，Current View 才会进入类似“安徽省 · 340000”的省级视图。

如果更新代码后浏览器仍显示旧行为，请先执行一次 `Ctrl + F5` 强制刷新。新版使用新的地图缓存键，通常不需要手动清理 Session Storage。
